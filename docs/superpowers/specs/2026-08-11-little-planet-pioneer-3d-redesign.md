# 《꼬마 행성 개척자: 별빛 개척대》 3D 리디자인 설계서

- 상태: 사용자 승인 방향
- 대상: 초등학교 5~6학년
- 플레이: 1인, 3~15분, 키보드·마우스·터치 대응
- 우선순위: 게임 같은 첫인상과 즉시 이해되는 상호작용 > 장식적 디테일

## 1. 문제 정의와 목표

현재 MVP는 게임 규칙은 갖췄지만 여러 DOM 패널이 화면을 둘러싸 대시보드처럼 보인다. 3D 전환의 목적은 정보를 더 많이 보여주는 것이 아니라, 학생이 로버를 움직이고 행성을 직접 회복시키는 느낌을 주는 것이다.

성공 기준:

1. 첫 화면에서 메뉴 설명을 읽지 않고 5초 안에 플레이 장면과 이동 방법을 이해한다.
2. 중앙 플레이필드가 평상시 HUD에 가리지 않는다.
3. 로버 이동 → 장소 조사 → 시설 배치 → 생산 확인의 핵심 루프를 3분 안에 경험한다.
4. 기존 미션·자원·로봇·저장 규칙은 유지하고 렌더링 계층만 교체한다.
5. WebGL이 약하거나 실패해도 기존 2D 플레이 화면으로 안전하게 돌아간다.

## 2. 게임 판타지

게임 제목은 《꼬마 행성 개척자: 별빛 개척대》로 표시한다. 학생은 작은 탐사 로버의 조종자이며, 황량한 행성 조각을 탐험해 빛·물·생명을 되돌린다. 로봇 동료는 로버를 따라다니고 능력을 사용할 때 짧은 색상·입자 연출을 만든다.

전투, 공격, 파괴, 게임오버는 사용하지 않는다. 실패는 “아직 회복이 덜 됐어요”라는 부분 결과와 재도전 선택으로 표현한다.

## 3. 카메라와 조작

- 기본 카메라: 로버를 내려다보는 3/4 아이소메트릭 PerspectiveCamera
- 카메라 회전: 마우스 드래그 또는 화면 가장자리 회전 버튼
- 이동: WASD·방향키·터치 스틱 중 하나
- 조사/건설: Space·Enter·화면의 상호작용 버튼
- 카메라 입력과 DOM 메뉴 입력은 명시적으로 분리한다.
- 모달·설정·로봇 상세창이 열리면 카메라 드래그와 이동을 잠근다.
- 로버가 움직이면 “이동 키를 눌러 보세요” 안내를 숨긴다.

## 4. 3D 장면 구성

### 행성

구형 행성 전체를 실시간으로 만들지 않고, 작은 부유 섬을 중심으로 한 저폴리 행성 조각을 사용한다. 중심 기지, 탐사 노드, 빈 건설 지점, 사건 지점이 서로 다른 색·형태·빛으로 구분된다.

### 로버와 동료

로버는 큰 바퀴와 밝은 전조등을 가진 단순한 저폴리 모델이다. 선택한 지원 로봇은 로버 옆에서 따라다닌다. 실제 GLB가 없을 때는 같은 실루엣의 primitive 조합을 fallback으로 사용한다.

### 시설

태양광 발전기, 물 재활용기, 부품 작업장, 생태 온실, 관측소, 통신 기지를 GLB 또는 primitive factory로 표현한다. 배치 전에는 투명한 홀로그램, 배치 후에는 색상과 작은 생산 애니메이션으로 상태를 구분한다.

### 사건

얼음 동굴·외계 생명체·금속 광맥·갈라진 케이블 같은 사건은 작은 landmark와 아이콘으로 표시한다. 가까이 다가가면 DOM 선택 팝오버를 연다.

## 5. 저크롬 HUD

기본 화면에는 다음 세 요소만 고정한다.

- 좌측 상단: 한 줄 목표 칩
- 우측 상단: 물·에너지·부품 compact status strip
- 하단 중앙: 가까운 대상의 상호작용 prompt

미션 상세, 로봇 설명, 전체 건설 목록, 설정은 기본적으로 닫힌 drawer/modal에서 연다. 화면 모서리마다 동일한 패널을 배치하지 않고 중앙과 하단 플레이 공간을 보존한다.

## 6. 자산 파이프라인

- 장기 런타임 계약은 GLB/glTF 2.0으로 통일한다.
- Blender 또는 코드 기반 primitive에서 source를 만들고 GLB로 정규화한다.
- 피벗, 단위, 이름, 방향을 게임 상호작용 기준으로 고정한다.
- 반복 시설은 공용 재질과 인스턴싱을 사용한다.
- glTF Transform으로 prune·deduplicate·simplify를 수행한다.
- 초기 버전은 Draco 또는 Meshopt 중 하나만 선택하고, 텍스처는 작은 WebP 또는 KTX2 후보로 제한한다.
- 충돌이 필요한 로버와 건설 지점에는 단순 box/capsule proxy를 사용한다.
- 에셋 로드 실패 시 primitive fallback으로 플레이를 계속한다.

## 7. 런타임 경계

```text
simulation/       기존 TypeScript 미션·자원·로봇·생산 규칙
render/app/       Three.js renderer, scene, camera, resize, context recovery
render/objects/   planet, rover, robots, buildings, landmarks
render/loaders/   GLB loader, cache, fallback factories
ui/               DOM HUD, prompts, drawers, settings
diagnostics/      FPS, WebGL fallback, debug capture
```

Three.js 객체는 규칙의 원본이 아니다. 게임 상태가 먼저 바뀌고 렌더러가 그 상태를 반영한다. 기존 Phaser 화면은 3D 로딩 실패나 WebGL 미지원 시 fallback 화면으로 남긴다.

## 8. 단계적 전환

1. 3D shell: 카메라·빛·행성 조각·로버 이동·저크롬 HUD
2. 상호작용: 건설 지점 선택, 사건 landmark, DOM prompt
3. 전략 연결: 시설 GLB/primitive, 로봇 동료, 생산 이펙트
4. 전환: 기존 미션·저장·결과 화면 연결
5. 최적화: GLB 검증, LOD, 압축, resize/context-loss, 모바일 점검

각 단계는 기존 2D 회귀 테스트를 깨지 않고 독립적으로 실행 가능해야 한다.

## 9. 검증

- Three.js 장면 부팅과 WebGL fallback
- 1024×768·768×1024 resize와 가로 넘침
- 로버 WASD/키보드·pointer·터치 입력
- 카메라 입력 잠금과 modal 복귀
- 건설 preview와 실제 simulation 결과 일치
- GLB 로드 실패 시 primitive fallback
- 외부 네트워크·광고·채팅·개인정보 수집 없음
- reduced motion, 저사양 renderer, context-loss 복구 경로
