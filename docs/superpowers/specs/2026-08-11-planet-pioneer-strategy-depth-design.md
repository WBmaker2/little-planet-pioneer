# 《꼬마 행성 개척자》 전략 깊이 확장 설계서

- 상태: 사용자 진행 승인
- 대상: 초등학교 5~6학년, 교사 관찰형 10~15분 플레이테스트

## 목표

기존 MVP의 선택·건설 루프에 지원 로봇, 시설 생산 턴, 배치 보너스 미리보기를 연결한다. 학생이 “무엇을 먼저 할까?”를 판단할 수 있게 하되, 자원 손실은 작고 결과는 즉시 이해되게 만든다.

## 핵심 규칙

### 지원 로봇

미션 시작 화면에서 한 번에 한 로봇을 선택한다. 선택값은 PlanetState에 저장한다.

| 로봇 | 능력 |
|---|---|
| 물방울 | 미션 시작 물 +2 |
| 반짝이 | 태양광 발전기 생산 +1 |
| 똑딱이 | 첫 번째 사건 선택 시 선택 보너스 자원 +1 |
| 새싹이 | 회복도 증가량 +2 |

보너스는 결정적이고 확률형이 아니다. 로봇 선택은 선택하지 않아도 기본값으로 진행할 수 있다.

### 시설 생산 턴

건물 배치가 성공할 때마다 생산 턴을 1회 처리한다. 건설 비용을 먼저 차감하고, 생산·회복 효과를 적용한다.

- 태양광 발전기: 에너지 +2, 평원 +1, 반짝이 +1
- 물 재활용기: 물 +2, 빙하 +1, 인접 온실 +1
- 부품 작업장: 부품 +1
- 생태 온실: 회복도 +4, 새싹이 +2, 인접 재활용기 +2
- 관측소: 회복도 +2
- 통신 기지: 에너지 +1, 회복도 +1

시설 생산 효과로 자원은 음수가 되지 않는다. 한 번 배치된 시설의 생산은 같은 배치 턴에 한 번만 적용한다.

### 배치 보너스 미리보기

선택한 건물과 각 빈 타일의 예상 결과를 계산한다. 미리보기에는 비용, 생산 자원, 회복도 변화, 지역/인접 보너스를 문장으로 표시한다. 배치 성공 시 미리보기와 동일한 결과가 실제 상태에 반영된다.

## 데이터 흐름

`로봇 선택 → 초기 상태에 로봇 보정 → 건물 선택 → 타일 미리보기 → 배치 비용 차감 → 생산 턴 적용 → 체크포인트 저장`

핵심 계산은 Phaser와 분리된 순수 함수로 둔다.

- `applyRobotBonus(mission, robotId)`
- `calculatePlacementPreview(state, mission, type, position, robotId)`
- `placeBuilding(state, mission, type, position, robotId)`
- `resolveEvent(state, mission, choiceId, robotId)`

기존 저장 데이터에는 로봇이 없을 수 있으므로 `robotId`는 `null`로 복구한다.

## 플레이테스트

게임 안에는 식별자 없는 세션 관찰 기록만 남긴다. 로컬 메모리에서 시작·첫 행동·로봇 선택·미리보기 사용·도움 요청·완료 여부·소요 시간을 기록하며 서버 전송은 하지 않는다.

교사용 관찰표는 다음을 기록한다.

- 30초 안에 미션 목표를 말할 수 있었는가
- 로봇 능력을 읽고 선택했는가
- 미리보기 문장을 이해했는가
- 자원 부족 원인을 스스로 설명했는가
- 도움 없이 첫 시설을 배치했는가
- 10분 안에 한 번 이상 전략을 바꾸었는가
- 재미 점수 1~5, 어려움 점수 1~5

실제 학생 참여와 보호자·학교 승인 없이는 플레이테스트를 자동으로 “완료” 처리하지 않는다.

## 안전·접근성

- 로봇은 확률형 보상이나 유료 요소가 아니다.
- 이름·학생 번호·계정 정보는 수집하지 않는다.
- 미리보기는 색상 외에 아이콘·문장·숫자를 함께 표시한다.
- 키보드 포커스와 44px 이상 조작 영역을 유지한다.
- 저사양 기기에서도 DOM 텍스트만으로 핵심 결과를 확인할 수 있다.
